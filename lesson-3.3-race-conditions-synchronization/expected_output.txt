Part 4: the same two ideas, on a GPU
  atomicAdd() on a GPU is the same concept as std::atomic's fetch_add --
  a hardware-guaranteed, uninterruptible read-modify-write. lesson 7.6's
  reduction and the histogram kernel in the source pack both use it.
  __syncthreads() is a different tool for a different problem -- not
  protecting one shared value, but making every thread in a block wait
  at the same point before any of them proceed. lesson 7.5's tiled
  matmul kernel called it twice per tile iteration: once after loading
  shared memory, so no thread reads a tile before every thread finished
  writing it, and once after computing, so no thread overwrites the tile
  for the next iteration while a slower thread is still reading it.
